## Key Decisions
- **Decision**: Client-side tool search instead of Anthropic's native `defer_loading`
  - **Context**: Primary model is `moonshotai/kimi-k2.5` via OpenRouter, which doesn't support Anthropic's native tool search
  - **Rationale**: Works across all providers (OpenRouter, Anthropic, etc.)
  - **Alternatives rejected**: Native Anthropic `defer_loading` (provider-specific), always sending all tools (wasteful)

- **Decision**: Plan suppression for < 3 steps
  - **Context**: User complained that single-tool tasks showed verbose execution plans
  - **Rationale**: Simple tasks don't need visible plans; only multi-step tasks benefit from progress visibility

- **Decision**: Feature gated behind `tools.search.enabled` (default false)
  - **Rationale**: Zero risk to existing deployments; can be tested incrementally

## Lessons Learned
- The wrapper script `~/.picoclaw/wrapper.sh` on the Oracle VM handles Telegram notifications on crash/restart via Bot API. Never bypass it by running `picoclaw gateway` directly.
- Clean shutdown: `touch ~/.picoclaw/stop && tmux send-keys C-c`. The wrapper checks for the stop file and exits cleanly instead of restarting.
- After replacing the binary, remove the stop file before restarting: `rm ~/.picoclaw/stop && bash ~/.picoclaw/wrapper.sh`
- Existing mock types live in `pkg/agent/executor_test.go`: `mockLLMProvider`, `mockFailoverRouter`, `mockUsageRecorder`, `mockCustomTool`.
- The `Tool.Execute()` signature returns `*ToolResult` (not `(string, error)` — old pattern was migrated).

## Nuances & Edge Cases
- `ActiveToolSet.SearchTools()` holds both its own `mu` and `registry.mu` locks simultaneously. The lock order is always `ActiveToolSet.mu` → `registry.mu` to prevent deadlocks.
- `tool_search` is implicitly added as a core tool in `NewActiveToolSet()` — don't add it to the config's `core_tools` list.
- `ActiveToolSet.Reset()` is called at the start of each `LLMExecutor.Run()` call, so deferred tools loaded in one message don't persist to the next.
- The cron migration runs on `loadStore()` — old jobs with `"kind": "agent_turn"` are automatically converted. The `deliver` field is removed from JSON. Already-migrated jobs (with `"kind": "command"/"deliver"/"agent"`) are untouched.
- On the deployed VM, `~/.picoclaw/workspace/cron/jobs.json` has 2 jobs already migrated to `"kind": "command"`.
